# Zvia v0.1.2-beta

**Deployments — change tracking, smarter clustering, and a redesigned landing site.**

Zvia v0.1.2-beta extends Deployments with topology snapshots and per-deployment diffs so you can tag a known-good state and see exactly what changed when something breaks. Clustering now covers Docker Compose projects and non-nginx stacks, and the marketing site is rebuilt around the full Deployments story.

---

## What's new

### Change tracking

Every meaningful topology scan is recorded automatically into a rolling per-server history (up to 10 snapshots). Tag a snapshot — for example `stable` — to mark a known-good baseline, then diff against the live state or any other snapshot.

- **Automatic snapshots** — recorded when a scan produces a structural change (nginx sites, ports, containers, services, SSL, domains, relationships). Process PID churn from restarts is ignored.
- **Per-deployment scope** — every diff is scoped to one deployment. Comparing `api.example.com` never surfaces changes that only affected another application on the same server.
- **Tag badges** — deployment rows show the latest tag; click the badge to jump straight to a diff against live state.
- **Snapshot history** — **Show snapshots** opens a per-deployment table with timestamps, tags, and change summaries (e.g. "3 changes" or "Nginx config, Port"). Compare any two snapshots or a snapshot against **Current state**.
- **Change detail** — click a changed component in the diff view to see the exact before/after for that entity (field-level `sourceRef` diff, or full state for add/remove).

Snapshots are stored locally in `userData/topologyHistory.json`. Tagged snapshots are never auto-pruned; untagged entries roll off when the cap is exceeded.

### Smarter clustering

- **Docker Compose grouping** — containers sharing a Compose project are grouped via `docker_compose_service` entities and `member_of` relationships
- **Non-nginx deployments** — systemd-only stacks and raw port listeners surface as inferred deployments with lower confidence
- **Health improvements** — more accurate component and deployment health along the confirmed path from domain to backend

### Workspace UX

- Shared **WorkflowProgress** component for multi-step operations (Enable HTTPS, package installs) with consistent step indicators and streamed output
- IPC channel list consolidated into `ipcChannels.ts` as the single source of truth for preload allowlists and registry unregistration

## Technical notes

For contributors and reviewers:

- New `TopologyHistoryService` and `topologyHistory` store for persistent per-server snapshot history
- `diff.ts` and `summarize.ts` for deployment-scoped topology diffs and change summaries
- Renderer views: `SnapshotsView`, `SnapshotDetailView`, `DiffDetailView`, `ChangeDetailView`, `changeGroups.ts`
- `ServiceBase.ts` shared helpers for server-scoped services; `LogStreamRegistry` for log stream lifecycle
- OrbStack demo fixtures and scripts (`demo-setup.sh`, `demo-changes.sh`, `demo-restore.sh`) for change-tracking integration testing
- Unit tests for diff, history service, clustering, health, and change groups; integration tests extended for Compose and non-nginx topologies

Zvia does not auto-update. Install the new version over your existing copy — server profiles and settings are kept.

### macOS Gatekeeper

Unsigned open-source builds may show a security prompt on first launch. Right-click the app → **Open**, or remove the quarantine attribute:

```bash
xattr -cr /Applications/Zvia.app
```

### Upgrade from v0.1.1-beta

1. Download the installer for your platform from the links above
2. Install over the previous version
3. Reconnect to your servers — the first scan after upgrade starts building snapshot history

## Requirements

- macOS, Windows, or Linux desktop
- SSH key-based access to remote Linux servers (agent or key file)
- No agent required on the remote host

---

## Known limitations

- Topology discovery depends on nginx, standard Linux tooling, and optional Docker/systemd — unusual setups may show `unknown` or `likely` edges
- Snapshot history is local to each machine; it does not sync across devices
- Fleet-wide views across multiple servers are not in scope; everything remains server-scoped
- Code signing and notarization (macOS) are planned for a future release
