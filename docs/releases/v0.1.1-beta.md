# Zvia v0.1.1-beta

**Deployments — topology discovery for the server you selected.**

Zvia v0.1.1-beta adds a fifteenth tool: **Deployments**. Connect to a server and see how each domain is wired — from nginx and SSL through listening ports to systemd services, processes, and Docker containers — with evidence for every connection.

---

## What's new

### Deployments

The Deployments tool scans the selected server and groups resources by primary domain. One row per deployment; open a row to follow the path from domain to backend on an interactive topology canvas.

- **List view** — domain, overall health, and per-component chips (SSL, Nginx, Backend, Service, Files, Container)
- **Topology canvas** — nodes for domains, nginx sites, ports, services, processes, and containers; edge style reflects confidence (solid, dashed, dotted)
- **Inspector** — structured entity details, dependencies, and a **Why?** panel with evidence snippets (nginx directives, port bindings, process matches, Docker output)
- **Scan** — cached snapshots refresh automatically (60s TTL); explicit Scan forces full rediscovery with progress in the panel header
- **Shared backends** — when multiple domains proxy to the same port, deployments stay separate and an inline insight explains the shared resource

### Cross-tool navigation

Jump from related tools into the matching deployment:

- **Ports** — open a listener and follow **View in Deployments**
- **Docker** — link from a container to its deployment context
- **Nginx** — jump from a site to the topology node
- **Services** — link from a systemd unit when it maps to a backend

### Workspace UX

- **Applications** section added to the tool sidebar
- **Deployments opens by default** when you connect to a server (first empty workspace only)
- Keyboard shortcuts and command palette include the new tool

## Technical notes

For contributors and reviewers:

- New `app/src/main/services/deployments/` module — collector, parsers, inferrer, clusterer, health, insights, and `TopologyService`
- Shared topology types and cache TTL in `app/src/shared/topology.ts`
- Topology cache invalidates when Docker containers change or Nginx/systemd state is mutated
- Connection loss clears topology cache with other per-server service state
- Unit tests for parsers, clustering, health, and topology service; OrbStack integration tests for end-to-end discovery

### macOS Gatekeeper

Unsigned open-source builds may show a security prompt on first launch. Right-click the app → **Open**, or remove the quarantine attribute:

```bash
xattr -cr /Applications/Zvia.app
```

### Upgrade from v0.1.0-beta

1. Download the installer for your platform from the links above
2. Install over the previous version
3. Reconnect to your servers — Deployments will scan on first open

## Requirements

- macOS, Windows, or Linux desktop
- SSH key-based access to remote Linux servers (agent or key file)
- No agent required on the remote host

---

## Known limitations

- Topology discovery depends on nginx, standard Linux tooling, and optional Docker/systemd — unusual setups may show `unknown` or `likely` edges
- Fleet-wide views across multiple servers are not in scope; everything remains server-scoped
- Code signing and notarization (macOS) are planned for a future release
